# 15. 구글 시트 명단 동기화

관리자 → 설정에서 버튼 한 번으로 **구글 시트의 참가자 명단을 DB에 반영**한다.
명단의 원본은 시트다 — 사람을 넣고 빼는 일은 시트에서 하고, 앱은 읽기만 한다.

---

## 1. 왜 시트를 원본으로 두나

명단은 여러 사람이 만든다. 등록 담당자가 폼 응답을 정리하고, 조 편성 담당자가
확인하고, 회비 담당자가 표시를 한다. 그 과정이 이미 **시트에서** 벌어진다.

앱에 명단 편집 화면을 만들면 원본이 둘이 되고, 둘은 반드시 어긋난다.
그래서 앱은 편집 화면을 두지 않고 시트를 읽어 오기만 한다.

---

## 2. 흐름

```
관리자 → [구글 시트에서 동기화]
            │
            ├─ 서비스 계정 JWT 서명 → 구글 액세스 토큰 (1시간 캐시)
            ├─ Sheets API로 범위 읽기 (A:Z)
            ├─ 머리글 행을 찾아 이름·생년월일·전화번호 열 매핑
            ├─ 행 정규화 (19940101 → 1994-01-01, 01012345678 → 010-1234-5678)
            ├─ participants 업서트 (name, birth_date, phone)
            └─ DB에는 있는데 시트에 없는 사람을 목록으로 반환
```

관련 파일:

| 파일 | 역할 |
|---|---|
| [lib/google/auth.ts](../../src/lib/google/auth.ts) | 서비스 계정 JWT → 액세스 토큰 |
| [lib/google/sheets.ts](../../src/lib/google/sheets.ts) | Sheets API 호출 |
| [lib/sheet-participants.ts](../../src/lib/sheet-participants.ts) | 머리글 매핑 · 행 파싱 (순수 함수, 테스트 있음) |
| [admin/actions/sheet.ts](../../src/app/admin/actions/sheet.ts) | 동기화 서버 액션 |
| [admin/settings/SheetSync.tsx](../../src/app/admin/settings/SheetSync.tsx) | 버튼과 결과 화면 |

## 3. 열은 이름으로 찾는다

시트는 사람이 쓰는 문서라 열이 늘고 순서가 바뀐다. 위치를 고정하면
누군가 열 하나를 끼워 넣는 순간 동기화가 조용히 어긋난다.

그래서 **머리글 이름으로** 찾는다.

| 항목 | 인식하는 머리글 |
|---|---|
| 이름 | 이름, 성명, 참가자, name |
| 생년월일 | 생년월일, 생일, 출생, birth, birthday, birthdate, dob |
| 전화번호 | 전화번호, 전화, 휴대폰, 핸드폰, 연락처, phone, mobile, tel |

- 공백·괄호·하이픈을 지우고 비교한다 → `휴대폰 번호`, `연락처(본인)` 도 걸린다
- 완전히 같은 것을 먼저 찾는다 → `이름`이 `이름표`보다 우선
- 시트 맨 위 제목·안내 문구는 건너뛴다 (세 열이 다 잡히는 첫 행을 머리글로 본다)
- 세 열을 다 못 찾으면 **아무것도 읽지 않는다** — 엉뚱한 열을 이름으로 쓰느니 실패가 낫다

인식한 머리글은 결과 화면에 그대로 표시된다. 어긋나면 바로 보인다.

> [!important] 사람의 신원은 (이름, 생년월일, 전화번호) 세 값이다
> DB의 유니크 제약이 이 세 값이라, 시트에서 셋 중 **하나라도 고치면 다른 사람**이 된다.
> 전화번호 오타를 시트에서 고치면 → 새 사람으로 추가되고, 원래 행은
> 「시트에 없는 사람」에 나타난다. 그때 옛 행을 지우면 된다.

---

## 4. 지우지 않는다

시트에서 빠진 사람을 자동으로 지우지 않는다. **목록으로만 보여주고**
삭제는 관리자가 한 명씩 결정한다.

시트에서 행 하나를 실수로 지우는 일은 흔하다. 그런데 참가자를 지우면
체크인 기록·숙소 배정·조 배정이 함께 사라지고 되돌릴 방법이 없다.
목록에는 그 사람이 **체크인했는지 · 로그인을 연결했는지**를 함께 띄워,
지워도 되는 사람인지 판단할 수 있게 한다.

## 5. 설정

### 5.1 GCP — 서비스 계정 만들기

1. [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 선택(없으면 생성)
2. **API 및 서비스 → 라이브러리** → `Google Sheets API` 검색 → **사용 설정**
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정**
   - 이름은 아무거나 (예: `sheet-reader`)
   - 역할은 **주지 않아도 된다** — 시트 권한은 4번에서 공유로 준다
4. 만들어진 서비스 계정 → **키 → 키 추가 → 새 키 만들기 → JSON** → 파일이 받아진다

JSON 안에 `client_email`과 `private_key`가 있다. 이 둘만 쓴다.

### 5.2 시트 공유

받은 `client_email`(예: `sheet-reader@proj.iam.gserviceaccount.com`)을
**시트의 공유 버튼 → 뷰어로 추가**한다.

이 단계를 빼먹으면 403이 나고, 화면에 "시트를 읽을 권한이 없어요"로 표시된다.

### 5.3 환경변수

로컬은 `.env.local`, 배포는 Vercel → Settings → Environment Variables.

```bash
# 시트 주소를 통째로 넣어도 되고 ID만 넣어도 된다
GOOGLE_SHEETS_ID=https://docs.google.com/spreadsheets/d/1AbC.../edit

# 탭 이름이 따로 있으면 '참가자!A:Z' 처럼. 비우면 A:Z
GOOGLE_SHEETS_RANGE=참가자!A:Z

GOOGLE_SERVICE_ACCOUNT_EMAIL=sheet-reader@proj.iam.gserviceaccount.com

# JSON의 private_key 값을 따옴표째 그대로 붙여넣으면 된다 (\n 이스케이프 유지)
GOOGLE_SERVICE_ACCOUNT_KEY="-----BEGIN PRIVATE KEY-----\nMIIEv...\n-----END PRIVATE KEY-----\n"
```

`private_key`는 여러 줄이라 JSON 안에서 `\n`으로 이스케이프돼 있다.
그 형태 그대로 넣으면 되고, 코드가 실제 줄바꿈으로 되돌린다.

> [!warning] 서비스 계정 키는 비밀번호와 같다
> 저장소에 커밋하지 않는다. 유출되면 GCP에서 키를 삭제하고 새로 만든다.
> 권한은 **읽기 전용 스코프**(`spreadsheets.readonly`)로 제한해 두었다.

---

## 6. 실패했을 때

| 화면 메시지 | 원인 |
|---|---|
| 구글 서비스 계정이 설정되지 않았어요 | `GOOGLE_SERVICE_ACCOUNT_EMAIL` / `_KEY` 없음 |
| 시트를 읽을 권한이 없어요 (403) | 시트를 서비스 계정 이메일에 공유하지 않음 |
| 시트를 찾을 수 없어요 (404) | `GOOGLE_SHEETS_ID`가 틀렸거나 탭 이름 오타 |
| 머리글을 찾지 못했어요 | 이름·생년월일·전화번호 열이 없거나 이름이 다름 (§3) |
| 구글 인증 실패 | 키가 깨졌거나(줄바꿈 손상) Sheets API 미사용 설정 |

---

## 7. 안 한 것

- **자동 동기화(주기 실행)** — 사람이 누를 때만 돈다. 명단이 조용히 바뀌는 것보다
  누가 언제 맞췄는지 아는 편이 낫다고 봤다
- **시트에 쓰기** — 읽기 전용 스코프다. 체크인 결과를 시트에 되쓰려면 스코프와
  권한을 모두 올려야 하는데, 그만한 이득이 없다
- **조·숙소 열 읽기** — 지금은 이름·생년월일·전화번호만 본다.
  배정은 관리자 화면에서 한다
